Programación Basada en Simulación

Análisis de Programación Basada en Simulación

Objetivo

Dado un proyecto, donde cada tarea tiene una estimación de duración optimista O, mas probable M y pesimista P, y se conoce la lógica de precedencia entre las tareas, se desea construir un cronograma en donde:

  • Cada tarea tenga una duración determinista (fija) como en un cronograma tradicional.
  • La combinación de todas las tareas y sus relaciones (precedencias) conduzca a que la duración del camino crítico tenga una probabilidad de finalización objetivo deseada Px

Fundamento

Duraciones con incertidumbre

Cada tarea T tiene tres estimaciones:

  • O: duración optimista
  • M: duración más probable
  • P: duración pesimista

Además, cada tarea tiene una distribución de probabilidad FD, la cual puede ser:

  • Uniforme: todos los valores tienen la misma probabilidad; útil cuando no hay preferencia dentro de los límites.
  • Triangular: definida por (mínimo, moda, máximo); forma de triángulo; media = (a + m + b)/3; útil cuando solo se tienen estimaciones aproximadas.
  • Normal: simétrica y con forma de campana; apropiada para variaciones naturales alrededor de una media.
  • PERT (Beta-PERT): basada en (mínimo, moda, máximo) con suavizado; menor varianza que la triangular; común en estimaciones de proyectos.

Duración esperada

Si se modelara cada tarea con una distribución triangular o PERT, se puede calcula la duración esperada E[D] como:

E [ D i ] = O i + 4 ⁢ M i + P i 6

Utilizar solo E[D] como duración fija generará un cronograma que tendrá, en general, una probabilidad de 50% de completarse en la fecha programada (equivalente a lanzar una moneda al aire).

Para lograr una mayor confiabilidad (por ejemplo igual a P80), es necesario ajustar las duraciones individuales de cada tarea, pero no de forma arbitraria.

Algoritmo

Paso 1: Preparación de los datos

  1. Para cada tarea T, se debe registrar:
    • Sus duraciones estimadas: O, M y P
    • Su distribución: FD
    • Su conjunto de predecesoras: Pred
  2. Definir la cantidad de simulaciones N (por ejemplo 1.000).
  3. Definir el nivel de certeza desaeado para la finalización del proyecto Px (por ejemplo P80, es decir, que el proyecto tenga una probabilidad de cumplir con el plazo de finalización igual al 80%).

Paso 2: Simulación de Monte Carlo

Repetir N veces el siguiente proceso:

  1. Generar una instancia del proyecto: Para cada tarea T. generar una duración aleatoria d, usando la distribución de probabilidad FD. Las duraciones de cada tarea de esa instancia serán d(k).
  2. Calcular la duración total del proyecto para ese instancia: Implementar un algoritmo para calcular el camino crítico del proyecto D(k).

k corresponde a una iteración cualquiera.

Paso 3: Calcular el percentil objetivo del proyecto

A partir de los N valores de duración total D(1), D(2), ..., D(N), calcular el percentil objetivo deseado Px.

Paso 4: Filtrar simulaciones "exitosas"

Seleccionar todas aquellas simulaciones en donde el proyecto terminó dentro del percentil objetivo deseado (menor o igual).

S = { k ∈ [1, N] | D (k) ≤ P x }

Este conjunto de simulaciones S corresponde a aquellas donde el camino crítico del proyecto cumplió con la certeza objetivo.

Paso 5: Calcular duración ajustada por tarea

Para cada tarea T, tomar las duraciones simuladas d(k) del conjunto de simulaciones exitosas, es decir, donde k ∈ S y calcular el percentil Px condicional. Un percentil condicional es aquel donde se calcula el percentil objetivo, pero solo sobre un subconjunto de datos que cumplen cierta condición.

d i ajust = P x ( { d i (k) | k ∈ S } )

Este valor representa un valor seguro para la duración de la tarea T, condicionado a que el proyecto completo termine antes del valor asociado al percentil objetivo.

Paso 6: Crear el cronograma final

  • Asignar dajust como la duración fija de cada tarea T.
  • Construir el nuevo cronograma de la forma tradicional.

Conclusión

Como consecuencia, las tareas que componen el proyecto tendrán duraciones realistas, ajustadas al comportamiento estadístico real y sin depender de margenes o búffers asignados de forma subjetiva.

El método de programación basado en simulaciones condicionadas al cumplimiento del plazo global (Simulation-Based Scheduling) es un enfoque riguroso para construir cronogramas con alto nivel de certeza, el cual permite reportar avances de forma confiable.
